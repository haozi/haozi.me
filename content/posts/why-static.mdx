简短结论：**博客不需要服务器**。

## 一个博客真正需要什么

- 写一篇文章。
- 把它渲染成一个稳定的 URL。
- 让人能搜索到。
- 让人能订阅。
- 让我自己半年后回来，能很快改一处错别字。

这五件事里，没有一件需要数据库，也没有一件需要 SSR。

## SSG 的几个具体好处

1. **部署便宜**。一桶静态文件丢到任何 CDN / 对象存储就行。
2. **不会半夜被叫醒**。没有运行时，没有运行时崩溃。
3. **缓存几乎是免费的**。每一篇文章的 URL 都是公共可缓存的。
4. **历史快照可读**。`git log content/posts/*.mdx` 就是这个站完整的写作史。

## 用 Next.js 做 SSG 有什么不一样

很多人对 Next.js 的印象停留在「SSR 框架」，其实从 13 之后，App Router 默认就在尽量预渲染。开启 `output: "export"` 之后，每个路由会被编译成 HTML/CSS/JS 静态资源 — 跟手写 HTML 区别不大，但你拥有了：

- 路由系统、文件夹即路由
- React Server Components 在构建期跑（拿数据→渲染→丢掉服务端）
- `<Image />` 默认懒加载
- `next/link` 做客户端预取

```ts
// next.config.ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  output: "export",
  trailingSlash: true,
  images: { unoptimized: true },
};

export default nextConfig;
```

> 简单到出乎意料。你甚至可以把整个 `out/` 目录打成 zip 通过邮件发给自己。

## 它不擅长的事

- 动态搜索后端（我们用客户端静态索引解决）
- 评论（建议挂到第三方，比如 giscus / utterances）
- 任何依赖请求时间的逻辑（比如限速、A/B）

这些事博客本来也不该揽。
