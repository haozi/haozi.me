不是所有「数学」都需要先 `import sympy`。下面是几个写代码时确实掏出来用过的小招。

## 浮点比较：永远不要 `a === b`

```ts
const EPS = 1e-9;
function eq(a: number, b: number) {
  return Math.abs(a - b) <= EPS * Math.max(1, Math.abs(a), Math.abs(b));
}
```

绝对误差 + 相对误差混合，对 0 附近和大数都安全。
`EPS` 取多少看场景：可视化坐标用 `1e-6` 足够；金融用 `1e-9`，并且能不浮点就不浮点。

## Kahan 求和：抵消累加误差

把大量 small float 相加时，普通 `for` 会把低位丢掉：

```ts
function kahanSum(xs: number[]): number {
  let sum = 0;
  let c = 0; // 已经丢失的低位补偿
  for (const x of xs) {
    const y = x - c;
    const t = sum + y;
    c = t - sum - y;
    sum = t;
  }
  return sum;
}
```

> 在 100 万个 `0.1` 相加这种场景里，普通 sum 会有 ~1e-9 量级的偏差，Kahan 几乎为零。

## 整数 hash 混合：Murmur 收尾步

很多自定义哈希到最后一步都缺一个**雪崩**步骤。Murmur 收尾常用：

```ts
function fmix32(h: number): number {
  h ^= h >>> 16;
  h = Math.imul(h, 0x85ebca6b);
  h ^= h >>> 13;
  h = Math.imul(h, 0xc2b2ae35);
  h ^= h >>> 16;
  return h >>> 0;
}
```

适用于：你已经把若干字段累加 / 异或在一起，但担心高低位关联性太强。把结果丢进 `fmix32` 就能让 hash 表分桶均匀。

## 取模别用 `%` 直接做正负数

```ts
function mod(n: number, m: number) {
  return ((n % m) + m) % m;
}
```

JS 的 `%` 跟数学定义不一致（保留符号），上面这个版本永远返回 `[0, m)`。

## 二分法

```ts
function lowerBound<T>(arr: T[], target: T): number {
  let lo = 0;
  let hi = arr.length;
  while (lo < hi) {
    const mid = (lo + hi) >>> 1;
    if (arr[mid] < target) lo = mid + 1;
    else hi = mid;
  }
  return lo;
}
```

`lowerBound` 比 `Array.findIndex` 在已排序数组里快非常多。`>>> 1` 比 `Math.floor((lo+hi)/2)` 快、且不会在大数组上溢出（`lo+hi` 仍然受 2^32 限制，但日常够用）。
